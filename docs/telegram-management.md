# Telegram 管理

主菜单分为 **节点管理** 和 **Bot 管理**。Pages 地址和一次性配对码在「节点管理 → 添加设备」同一张卡片中。

## 用户权限

在「Bot 管理 → 用户权限」输入用户数字 ID 添加用户。重复添加同一 ID 可更改角色；用户列表支持分页。

| 角色 | 设备操作 | Bot 与群规则设置 |
| --- | --- | --- |
| 只读 | 状态、节点、SSH 信息、外部探测、请求最新信息 | 无 |
| 控制 | 只读功能，以及配对/移除设备、节点配置、服务维护、静音、重启、root Shell | 无 |
| 管理员 | 全部 | 添加、删除及修改所有用户和管理员；启停群聊、设置自动管群规则 |

所有管理员平级，可以删除最初部署时设置的管理员，但系统必须保留至少一位管理员。控制权限也包含设备 root Shell，只授予需要管理设备的人。

首次使用新版时，部署时的 Owner 和旧版指定群成员授权会一次性导入统一用户表；已存在的全局用户角色优先，Owner 初始化为管理员。之后权限完全由菜单管理，修改部署环境中的 Owner ID 不会覆盖菜单权限。旧群全员控制/管理员模式自动关闭；原全员只读语义统一为“全员可用 Bot”。

删除或降低用户权限后，设备领取尚未执行的命令时会复查权限并取消不再允许的命令；已执行的操作无法撤销。

## 启用群聊

1. 把机器人加入群；要使用管群功能，将机器人设为 Telegram 群管理员，授予删除消息、限制成员权限；置顶命令还需置顶消息权限。
2. Bot 管理员在目标群发送 `/id@机器人用户名`，复制负数群 ID。
3. 在「Bot 管理 → 群聊管理 → 启用群聊」添加此 ID。
4. 从群列表进入群设置。新群的“全员可用 Bot”、自动过滤、防刷屏、入群验证均默认关闭。

启用群后，全局管理员/控制/只读用户的角色自动生效。“全员可用 Bot”开启时，其他普通群成员获得只读使用权；关闭时，未授权成员不能调用节点查询。Bot 管理员始终可用。未启用群不接受设备控制或自动管群，仅允许 Bot 管理员查询群 ID。

群内命令需要 `@机器人用户名`，例如 `/start@MyNodeBot`。点击菜单按钮无需 @。节点信息发到群里会被群成员看见；关闭“全员可用 Bot”不会隐藏已经发送的历史消息。

普通聊天不触发节点菜单。自动过滤与入群验证则会处理未 @ 的消息/入群事件。Telegram 原生群管理员可以使用管群命令，但不会因此获得节点或 Bot 管理权限。

## 自动管群

每个群独立配置；不使用时保持关闭。

- **风控规则**：屏蔽词、链接、转发、图片、视频、文件、贴纸、语音、动图。每条规则选择删除、删除并禁言一小时、删除并封禁。屏蔽词按字面包含匹配，每群最多 100 条；不运行用户输入的正则表达式。编辑后的消息、媒体说明中的链接也会检查。
- **覆盖范围**：普通成员、已授权 Bot 用户、Telegram 群管理员和匿名管理员发出的内容都会进入规则检查。管理员或匿名管理员命中“禁言/封禁”规则时只删除违规消息，不尝试限制管理员本人。
- **防刷屏**：同一可识别用户在固定 10 秒窗口超过 8 条消息时，删除触发消息并禁言一小时。Telegram 不提供匿名管理员的真实用户 ID，因此匿名管理员不参与按用户计数的防刷屏。
- **入群验证**：超级群新成员先临时禁言，5 分钟内完成算术按钮验证，最多 3 次。仅本人能验证，验证不会授予 Bot 或节点权限。超时由每分钟维护任务移出，可重新加入。每次维护最多处理 5 个待处理验证；大量同时入群时可能延后。Telegram/维护任务异常时，临时禁言最多 10 分钟，不会永久困住成员。
- **欢迎语/群规**：纯文本；欢迎语支持 `{name}`，发送 `-` 清空。验证开启时通过后再欢迎。
- **清理进退群通知**：删除 Telegram 的进退群系统消息。
- **最近处理记录**：仅保存操作、用户 ID/匿名 sender_chat 标识、时间，保留 7 天，不保存消息正文。

管理员仍受内容规则检查，但不会被 Bot 自动禁言或封禁。匿名管理员/频道身份没有可用的真实用户 ID，因此可以删除违规消息，却不能还原真实发送者身份或对真实用户执行限制。

如果群里发言名称显示成群名而不是个人名，这是 Telegram 的“匿名管理员/保持匿名”行为，不是 Bot 改名。要恢复个人名字，需要在 Telegram 群管理员设置里关闭对应管理员的匿名模式；Bot 无法从 `sender_chat` 反推出真实用户。

这是轻量群管理，算术验证可减少简单广告机器人，不能保证阻止所有自动化。大群高并发还受 Cloudflare 套餐及 Telegram API 限流影响。

## 常用管群命令

回复目标消息执行（把 `MyNodeBot` 换成实际用户名）：

```text
/del@MyNodeBot
/ban@MyNodeBot
/unban@MyNodeBot
/kick@MyNodeBot
/mute@MyNodeBot 60
/unmute@MyNodeBot
/pin@MyNodeBot
/unpin@MyNodeBot
```

也支持数字 ID：`/ban@MyNodeBot 用户ID`、`/unban@MyNodeBot 用户ID`、`/mute@MyNodeBot 用户ID 分钟`。禁言支持 1–43200 分钟。`kick` 移出后允许重新加入；`ban` 封禁，需 `unban` 解除。

其他：`/rules@MyNodeBot` 查看群规；`/grouphelp@MyNodeBot` 查看命令；`/cancel` 取消菜单输入。群内交互输入要在开头加 `@MyNodeBot`。匿名管理员不能执行需要确认真实操作者身份的 Bot 管理命令。

## 部署与验证

这次只更新 Cloudflare：运行仓库 `cloudflare/deploy-complete.sh`，填写原 Worker、D1、Pages 名称，复用原数据。部署会创建新增表、更新 Webhook 的编辑消息和成员事件订阅、将维护任务改为每分钟。设备心跳/DDNS 的 5 分钟周期不变，不需要重装路由器或 VPS。

机器人必须在群中具有相应 Telegram 权限。可从「群设置 → 权限检查」确认；启用自动规则前也会检查权限。权限检查成功不代表所有真实群事件已完成验证，部署后请分别用普通成员、Telegram 管理员和匿名管理员消息测试屏蔽词场景。

本地验证（Node.js 22.13+，推荐 24）：

```bash
cd cloudflare
npm ci
npm run check
npm test
```

测试使用 SQLite 和模拟 Telegram API，不向真实群发送消息或执行处罚。

参考：[Telegram Bot API](https://core.telegram.org/bots/api)、[TLG_JoinCaptchaBot](https://github.com/J-Rios/TLG_JoinCaptchaBot)。参考入群验证流程；本实现独立编写，没有复制该项目 GPL 代码，也不需要部署它的 Python 服务。
